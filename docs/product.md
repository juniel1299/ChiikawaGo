# CHII WORLD 제품과 MVP

기준은 루트 `PROMPT.md`와 승인된 Phase 0~4 계획이다. **확정**은 제품 원칙/사용자 선택, **초기 기본값**은 이번 구현 결정, **후속**은 아직 구현하지 않은 범위를 뜻한다.

## 목적과 사용자

치이카와 테마의 위치 기반 수집 서비스다. 개발의 목적은 기능 완성뿐 아니라 도메인, 트랜잭션, 동시성, 테스트, 운영의 선택 이유를 학습하는 것이다. 초기 사용자는 캐릭터를 수집하는 회원과 캐릭터·Spot을 관리하는 운영자다.

## 첫 핵심 MVP — 확정

Phase 6까지 다음 흐름을 API 통합 테스트와 Django Admin으로 검증한다.

1. 이메일·비밀번호로 가입하고 JWT로 인증한다.
2. 운영자가 캐릭터, Variant, Spot을 등록한다.
3. 회원이 좌표를 입력해 주변 활성 Spot을 조회한다.
4. 적합한 Spot에서 유효기간이 있는 Encounter를 발급한다.
5. 서버가 소유권·만료·위치·중복을 검증하고 Capture 결과를 결정한다.
6. 성공 결과를 Collection에 정확히 한 번 반영한다.

현재 Phase 0~4는 1~3의 기반과 API까지 제공한다. 제품 전체 MVP가 완료된 것은 아니다. 웹은 가입·로그인·계정 확인·로그인 연장·로그아웃만 제공한다. 위치 지도와 포획 화면은 만들지 않는다.

## 단계별 경계

| 단계 | 범위 |
|---|---|
| 0~1 | 저장소, Docker, 규약, 도메인/DB 설계, 프레임워크 골격 |
| 2~4 | 계정/JWT, 캐릭터/Variant, Spot/PostGIS/Nearby |
| 5~6 | Spawn Rule, Encounter, Capture, Collection |
| 7~11 | Community, News/Crawler, 비동기, Batch Console, 필요한 Redis 활용 |
| 12~16 | Flutter/GPS/Map, Push, Cloud, Observability, 부하 분석 |

아이템·스탬프·배지·지역 보상·이벤트·교환·날씨 기반 Spawn은 후속 요구사항이다. Unity, AR, 3D, Kafka, Kubernetes, H3는 필요성이 확인될 때만 검토한다.

## 검증과 제품 한계

- 주변 조회는 클라이언트가 전달한 좌표와 거리 조건을 검증한다. 실제 방문이나 GPS 위조 방지를 보장하지 않는다.
- 현재 사용자 위치를 저장하거나 로그에 남기지 않는다.
- 계정은 아직 이메일 소유 확인, 비밀번호 재설정, OAuth를 지원하지 않는다. 공개 운영 전 요구사항으로 다시 검토한다.
- 운영자는 Django Admin으로 데이터를 관리한다. 자체 Next.js Admin은 실제 운영 흐름이 구체화된 후 만든다.
- Flutter의 실제 GPS·지도 사용 경험은 Phase 12의 별도 완료 조건이다.
